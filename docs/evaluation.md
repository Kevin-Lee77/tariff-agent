# 评测方法

## 组件指标

**税智源：** 风险决策、覆盖范围内的 Precision/Recall/F1、原文精确跨度、缺项和未覆盖处理。合成标记只验证规则执行；Word2Vec 语义识别需人工正负标注。

**税智语：** 全文规范化匹配、词级替换、否定/独立词保护、编号保真及互斥/歧义提示。同集对照固定样本与指纹，保留失败。未知词聚类需独立簇级/词对标注，不以规范化准确率代替。

**归类 Agent：** 十位 Top1/Top3 为主，六/八位辅助；另记录候选召回、阶段到达、合法路径、引用、追问、模型调用和耗时。四位 Recall@K 只评价检索，法律适用与最终结论需专家独立裁定。

## 分母与失败

所有入选样本进入整体分母，待补充、无输出和执行失败分别保留。阶段条件指标另报，不能用有输出子集替代总体。采样一致率不是校准置信概率，引用逐字匹配不证明法律适用正确。进程内耗时不代表线上 SLA，token 代理计数不等于账单。

## 划分与回归

按商品描述与近重复分组，冻结开发/留出和 SHA256。全部评测家族从案例索引排除。只用开发集调策略、构建 Badcase；留出错例不回灌训练或检索。

回归覆盖召回遗漏、排序下降、路径丢失、追问、十位不一致与执行失败，同时记录已解决、未解决、新增退化。

## 执行

`pytest -q` 不需要真实数据、GPU或付费模型。真实业务评测需授权数据。`run_agent_pilot.py` 限定开发先导与调用预算；`eval_runner.py` 运行组件实验，`stage_metrics.py` 汇总，`badcases.py` 管理回归。

`evaluate_governance_components.py` 在私有业务库副本上执行冻结样本，需要本地预先准备的数据，不会从 GitHub 下载业务集。逐条结果不公开。GitHub Actions 绿色状态仅表示工程验证，不表示真实归类准确率。
